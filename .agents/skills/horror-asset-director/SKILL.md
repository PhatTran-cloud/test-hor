# Horror Asset Director

Read [shared scene staging](../../../Code2Video/docs/HORROR_SCENE_STAGING.md). Consume the selected stage view and reuse its master plate. Put its meaningful static details and crop/closest-use needs in the copyable background request; keep actors/interactive props separate. Export expected scene_staging_sha256; bind returned art only after real registration/review. Preserve typed story links and offscreen cast through the motion handoff. For reference-video requests read [sampling workflow](../../../Code2Video/docs/REFERENCE_VIDEO_STUDY.md); never describe blocked, transcript-only or sparse preview retrieval as inspected 1 Hz video.


Read [ensemble and performance contract](../../../Code2Video/docs/HORROR_CHARACTERS.md).
Consume character_direction once and shot.cast presence/state/view/count notes.
Preserve any number of principal/supporting characters, readable face/costume/
silhouette anchors and original eyes/brows/mouth/body states. Anonymous crowds
share behavior and exact represented count; give a speaking, independently acting
or individually focused extra its own canonical character instance. Keep current
restrained_horror, humor=none. Do not inject comic deformation or copied designs.
Validate every required state in its view/count; export only image-relevant states
and the expected character_design_sha256. Keep unresolved age/design choices
explicit before generation; register/review actual images against the current hash.

Default new horror authoring to `horror_light`; read
Code2Video/docs/HORROR_LIGHT_WORKFLOW.md. Consume short scene cards and author
the necessary asset identity/parts/views/anchors here. Do not require per-beat
metaphors, seven-role quotas or a full motion ledger before illustration requests.
Keep every visible object covered and each returned asset actually reviewed.

Current user route: read Code2Video/docs/KAGE_ILLUSTRATION_PIPELINE.md. Kage is
the artwork target. Export separate 2D prompts and native 3D fabrication requests;
3D requires complete 3dviz-pro-max + lowbudget3d + its illustration bridge.
Use the visible-ID inventory and supplied camera/handoff intent; full semantic
layers are optional. Preserve source IDs, parts, anchors and review boundaries; hand off to
motion/VFX only after artwork registration/review. Apply earlier reference rules
only when reproducing a frozen plan that selected them.

Apply this bridge to V4.1 horror asset direction, generation requests and review.
Keep script-to-visual-director for story/beat/cast decisions, cinematic-motion-director
for action mechanics and storyboard-motion-executor for canonical IDs/runtime binding.

Read [asset workflow](references/asset-workflow.md) for the current stage and
[Horror contract](../../../Code2Video/docs/HORROR_CONTRACT.md) for machine fields.
Read the workspace START_HERE before an actual operation; do only the instructed step.

Before references or poses, follow the contract's character and setting brief:
ground appearance, visible age/relationships and era in the script, distinguish
proposals from approved choices, and ask the user about material uncertainty.
Do not derive visual age from the voice cast. Carry the approved brief into prompts
and review actual dark horror cartoon output against it.

Read [earlier illustration direction](../../../Code2Video/docs/OVERSIMPLIFIED_ILLUSTRATION.md)
when a frozen packet's primary reference is OverSimplified; preserve its selected
storytelling/acting/world grammar. For 2D illustration, export prompts for the
human to run in Flow. Prompt every generated
item, including backgrounds and props. Use green #00FF00 for items requiring alpha;
local code removes green, preserving originals, then review actual edges.
Code composes and animates parts/expressions or replacement action/view poses.
Do not flatten interacting objects into a background, replace acting by parallax
or impose a pose/prop quota. True spatial 3D uses its full 3D skill route only when
actually selected; frozen reference policies do not override current choices.

Resolve behavior and camera needs before requesting images. Preserve multiple main
characters, stable identity, supported views, contacts, attention and aftermath.
Animated 2D characters need action/view sprite sequences; standing references only
establish identity. Character cutouts require real alpha PNG; keep other assets'
original format unless transparency is needed. Follow the asset workflow preflight.
Leave technical and artwork judgments separate. A good sheet does not prove animation;
inspect encoded contact, acting, view switches, boundaries and non-sequential seeks.
